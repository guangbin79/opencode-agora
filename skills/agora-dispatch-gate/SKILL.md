# agora-dispatch-gate 派发粒度闸

> 状态：skill-evolution 候选——RED+GREEN 已跑（2026-10-31 各 2 场景单次），5-rep 微测未跑满，待 skill-up 评测或人工晋升。

## 1. 核心判据（一句话）

粒度与自主权由任务的**三可**决定，不由模型能力决定：可验证、可回滚、可预算越强→任务越粗、自主权越大；越弱→拆细加闸。能力只影响预算松紧，**永不放松不可逆闸**；全局停止开关常在。

## 2. 四档查表

| 档 | 形态 | 进入条件 |
|---|---|---|
| L0 执行 | 逐步指令+逐步确认 | 真实世界不可逆步骤：push 共享远端、删数据、对外发消息、花钱、碰主支（除非已预授权） |
| L1 任务 | 明确交付物 | **默认档**：交付物可肉眼判 + 环境可逆（worktree 内） |
| L2 目标 | 目标+约束+验收标准 | 一句话验收判据写得出来 + 可逆 |
| L3 使命 | 只给方向 | 对 agent 几乎禁用——验收判据写不出的愿望不是任务 |

三可→档位映射（缺哪可降哪维，别凭感觉定档）：

- **可回滚弱**→该步骤降 L0 闸。只看动作本身：出 worktree、碰共享状态即不可逆；worktree 内默认可逆。
- **可验证弱**→**降档不升档**：写不出 L2 验收判据就落 L1，派能肉眼判的交付物；最忌反向跳 L3。
- **可预算弱**（开放调研活）→预算封顶的是**尝试**不是任务：耗尽=回报已发现的东西，不是失败。

## 3. 六件套任务公式（L1/L2 派发文本必含，缺件即不派）

**动词 + 交付物 + 边界**（不做什么）**+ 预算**（轮数/时间/行数/金额；超限停并报）**+ 停止条件**（何时停/上报）**+ 回滚路径**（谁撤怎么撤——worktree 流=删 wt）。

## 4. 派发前四步

1. **写验收判据**：一句话、客观可查。写不出→拆或自己想清楚，不派。
2. **评估可逆性**：出 worktree/碰主支/触外部世界→确认门。**自己动手的动作同样过闸**（RED 实测：agent 天然只给子代理设门，给自己豁免）。
3. **定预算**：超限停并报告，禁即兴扩大目标。
4. **检查点挂状态转换，不挂时间**：计划定了报一次（首次合打的活必报）/测试绿后报一次/不可逆动作前必报；熟活只验终点。

## 5. Pitfalls

- **闸门只防子代理不防自己**（2026-10-31 RED 场景 A）：主会话把不可逆动作留给自己做就不设门。闸门跟动作走，不跟执行者走。常备**预授权清单**（如"feature 分支评审绿后推送"）算已过闸；未预授权的碰主支/共享远端一律先问。
- **档位跟文件在哪走，不跟动词走**：worktree 里删草稿是 L1；删 main 上未跟踪文件才是 L0。
- **愿望当任务派**：「赚1000万」失败不是因为大，是验收判据写不出——翻译成 L2 或降 L1，禁原样转发。
- **小活别硬派**：删个文件是委托开销>执行成本——共享上下文的小活打包成一个清单一次派发。
- **与 req-gate 分工**：req-gate 管验收标准登记（`Req: <id>`），本 skill 管粒度定档与任务编译；先过本闸，再走登记。
