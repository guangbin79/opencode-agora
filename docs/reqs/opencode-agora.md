# opencode-agora 需求

- 日期：2026-10-26　状态：待用户批准
- 前身：`docs/reqs/agora-v2.md`（v1 概念基底稿）已废弃删除——本稿为 greenfield 重写
- 约定：实现与测试携带 `Req: F<n>` 锚；验收标准均为可执行判据

## 1. 问题定义

一个开发者 + 多个 AI agent，单机并行开发多个 git 项目。四个痛点：

1. agent 直接改主检出——工作区污染、改动无隔离
2. 跨项目任务没有编排——谁在干什么、干到哪了，说不清
3. 派出去的 agent 是黑盒——失联、卡死、跑飞，靠人肉发现
4. 人↔agent、agent↔agent 没有实时沟通通道

**opencode-agora = opencode v2 上的多 agent 委托协作层**：强制隔离、全程留痕、双向实时、自愈。

## 2. 用户与角色

单机、单人类用户。

| 角色 | 定义 |
|---|---|
| 人 | 唯一决策者，经 opencode 主会话驱动一切 |
| dispatcher | 主会话（或其派生会话）作为执行臂，可派发任务 |
| worker | 被派发的会话，只在专属隔离环境中干活 |

**自主度（用户 2026-10-26 裁定）：全自主委托**——人只说目标、全程不管、回头只看结果。推论：派发无确认门；**verify 绿即自动合并**（不等人点头）；过程中失败不打扰人，只在结果中呈现。

已知的风险转移（用户知情接受）：无人把关后，**verify 命令是唯一质量闸**；兜底 = F7 原子回滚 + F8 完整审计。

## 3. 核心场景（验收以此为纲）

| 场景 | 一句话 |
|---|---|
| S1 单仓委托 | "修 X" → 建任务+隔离环境+派发 → 干活 → verify → 自动合并 |
| S2 跨仓委托 | 任务跨两仓 → 各自派发，链上可见 |
| S3 过程沟通 | worker 发现歧义 → 实时问 → 实时答 → 继续，不挂起 |
| S4 失联自愈 | worker 卡死 / 任一服务重启 → 链上自动发现、恢复或上报 |
| S5 强制兜底 | 任何会话绕过直改仓库 → 拦下并引导正道 |
| S6 回看结果 | 人回来一句"进展如何" → 完成/已并/失败/阻塞 一目了然 |

## 4. 功能需求

### F1 强制隔离执行（S5）
git 仓的代码写入只发生在委托的专属隔离环境内；会话须持有效凭据（活动任务 + 环境归属，cwd ∈ 该环境），否则插件在工具层拒绝并引导派发。豁免面：非 git 目录、临时目录、显式 OFF 开关。
**验收**：无凭据写 git 仓必拒且含引导；持凭据 cwd∈环境放行；豁免面三例放行；opencode-agora 自身仓不豁免（自食狗粮）。

### F2 任务登记（S6）
每个委托有身份（id）、状态、归属链记录。任务为**平表**（无 deps/parent——编排顺序由 dispatcher 的派发与消息节奏表达）。
**验收**：任务创建后 id/状态/归属可查；状态迁移由服务权威记录。

### F3 派发与链
dispatcher 经服务派发 worker（opencode API create+inject）；支持嵌套派发，**链深上限**（默认 5）与并发配额（默认值 builder 定）硬约束。
**验收**：正常派发链建立并登记；超深度/超配额派发必拒且报因。

### F4 双向实时消息（S3）
dispatcher↔worker 结构化消息，方向不限：接收方会话存活即实时注入（≤5s）；不存活则落服务端消息库，恢复后补拉（拉取工具）。里程碑事件同时迁移状态+审计；过程性消息不进状态。无 ack 协议（inject 即送达、回 result 即回执）。
**验收**：在线投递 ≤5s（stub runtime 与真 opencode 各一轮）；离线消息恢复后可拉到；done/blocked 均产生状态迁移+审计行。

### F5 自上而下健康检查（S4）
服务内置定时器：对每个有在飞下级的 dispatcher 只探其**直接下一跳**；无全局巡检。stalled 阈值 warn/crit（默认 20/40min 可配）：warn→提醒该 dispatcher；crit→先恢复下级（重注入续跑），连续 3 次 crit→置 blocked 并实时通知 dispatcher。dispatcher 自身死亡→沿链上报，根链通知主会话（人）。
**验收**：stalled 注入触发 warn；3×crit→blocked+通知；全库无 cron/全局扫描代码路径。

### F6 崩溃恢复（S4）
权威状态原子持久化（tmp+rename+fsync）、启动重载。agorad（服务）或 opencode 服务任一重启：in-flight 链自动恢复——worker 死则按任务页+环境现场重注入续跑（同一凭据）；dispatcher 死则通知其父或根。worker 侧工具调用失败（服务暂不可用）本地排队重放。
**验收**：`kill -9` 服务→重启→状态一致+in-flight 续跑；opencode 重启→服务探测并走同一恢复路径。

### F7 验证门与自动合并（S1）
完成以**真实运行的 verify 命令**背书（服务在隔离环境内执行）；绿即**自动合并**（ff-only），合并后在目标仓跑集成 verify，失败 `reset --hard` 原子回滚并置 reopened。
**验收**：verify 败→不合并、状态 verify_failed、worker 收到输出尾部；集成 verify 败→目标分支字节级回到合并前+reopened；非 ff→拒并 reopened。

### F8 审计留痕
谁/何时/干了什么/证据，三份日志可对账：审计 JSONL（只追加只写）+ 项目 git 历史 + opencode 会话记录。
**验收**：任一任务可在审计日志 grep 出完整事件链且与 git 提交对应。

### F10 结果报告（S6）
人回看时一个入口给出汇总：完成/已自动合并/失败/阻塞 计数与明细、每件的结论与证据指针。
**验收**：S1 全链跑完后，报告含"已合并+结论+commit"；人为制造一例失败后报告含失败项与原因。

> **决策记录**：F9 逃生门（人的快速小改通道）**先不做**（用户 2026-10-26"逃生门先不要"；被拦即转派发。后需摩擦实证再议）。

## 5. 非功能需求

- 单机、零第三方依赖（服务与 MCP：Python 3 stdlib；插件：TS on Bun）
- opencode 服务 / agorad 任意重启不丢链；两进程互为看护互不纠缠
- 工具钩子拦截开销 <100ms
- 权威状态文件人类可读（JSON）
- 护栏硬边界：链深、并发配额、（builder 定）单委托预算

## 6. 非目标与反需求

非目标：多机同步、多用户、Web 管理界面、通用消息中间件、opencode 之外运行时、人动手逃生门。

反需求（出现即失败）：状态靠事件重放推导；cron/全局看门狗巡检；可绕过的强制；ack 类传输层协议。

## 7. 迁移与退役

`~/plaza` wiki 知识层保留；v1 的 `log/`、`board/` 归档不再增长，任务状态从零开始。v1 的 22 个 bash 脚本、notify 桥、HTTP 只读窗口（由服务 `/view` 承接其职责）、4321 行旧 smoke 套件全部退役。
